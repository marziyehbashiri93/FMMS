# FMMS Demo Frontend — مرکز کنترل نگهداری و تعمیرات ناوگان

دموی فرانت‌اند مستقل برای سامانه نگهداری و تعمیرات ناوگان (FMMS). این پوشه به بک‌اند وابسته نیست و صرفاً برای نمایش کامل جریان کاری به ذی‌نفعان ساخته شده است.

## اجرا

هیچ نصب یا build ای لازم نیست. فقط یک سرور استاتیک ساده کافی است:

```bash
cd demo-frontend_v2
python3 -m http.server 5500
```

سپس مرورگر را روی `http://localhost:5500` باز کنید.

ورود دمو (با `DEMO_MODE: true` در `config/env.js` — هر ایمیل/رمزی کار می‌کند):
- ایمیل: `demo@demo.com`
- رمز عبور: `demo`

## ساختار پوشه

```
demo-frontend_v2/
  index.html          پوسته اصلی (ورود + SPA)
  config/env.js       API_BASE_URL و DEMO_MODE
  js/api.js           لایه واحد API (واقعی یا mock)
  ...
```

## جریان کاری دمو (مدیر) — Workflow v2

```
ورود → خودرو → بازرسی راننده → خرابی → تصمیم توزیع → تایید ترابری →
تخصیص تعمیرگاه → پذیرش/رد تعمیرگاه → شروع تعمیر → درخواست قطعه / فاکتور خارجی →
اتمام تعمیر → تایید تحویل راننده → فعال‌سازی خودرو
```

APIهای کلیدی (طبق بک‌اند / `FMMS_API.yaml`):
- `POST /repair-orders/{id}/assign-workshop/` — تخصیص تعمیرگاه
- `POST /repair-orders/{id}/workshop-accept|reject/` — پذیرش/رد تعمیرگاه
- `POST /material-requests/` + approve/reject — درخواست قطعه
- `POST /repair-orders/{id}/external-invoices/` — فاکتور تعمیرگاه خارجی
- `POST /handovers/{id}/accept|reject/` — تایید/رد تحویل توسط راننده
- `GET /repair-orders/{id}/timeline/` — تاریخچه مراحل
- `POST /vehicles/{id}/activate/` — فعال‌سازی پس از پذیرش راننده

## سناریوی پیشنهادی دمو

۱. ورود با حساب مدیر (یا نقش مربوطه از منوی «مشاهده به‌عنوان»).
۲. **بازرسی روزانه خودرو**: انتخاب خودرو فعال، تکمیل چک‌لیست، ثبت بازرسی.
۳. **توزیع**: قابل‌استفاده یا غیرقابل‌استفاده / ارسال به تعمیر.
۴. **ترابری**: تایید + تخصیص تعمیرگاه؛ در صورت نیاز تایید درخواست قطعه / فاکتور.
۵. **تعمیرات**: پذیرش تعمیرگاه، شروع، قطعه/فاکتور، اتمام (خودرو → `WAITING_DRIVER_CONFIRMATION`).
۶. **تایید تحویل خودرو** (نقش راننده): پذیرش یا رد تحویل.
۷. **فعال‌سازی خودرو** پس از پذیرش راننده؛ داشبورد برای وضعیت نهایی.

## اتصال به بک‌اند واقعی

فقط دو خط در `config/env.js` را تغییر دهید:

```js
window.FMMS_CONFIG = {
  API_BASE_URL: "https://your-real-api.example.com/api/v1",
  DEMO_MODE: false,
};
```

از آن‌جا که `js/api.js` از همان مسیرها و ساختار درخواست/پاسخ واقعی سامانه (طبق `FMMS_API.yaml`) استفاده می‌کند، هیچ فایل دیگری نیاز به تغییر ندارد. توکن JWT به‌صورت خودکار در `sessionStorage` ذخیره و در هدر `Authorization` ارسال می‌شود.

## شبیه‌سازی نقش‌ها

با ورود مدیر، از منوی «مشاهده به‌عنوان» در بالای صفحه می‌توانید بین نقش‌های راننده، سرپرست توزیع، سرپرست ترابری و تعمیرکار جابه‌جا شوید. این فقط یک نمای بصری برای تسهیل دموی مرحله‌به‌مرحله است؛ در حالت دمو همه صفحات همچنان در دسترس مدیر باقی می‌مانند.

## معماری

این پوشه کاملاً مستقل است. کل پوشه `demo-frontend_v2` را می‌توان بدون اثر روی سرویس‌های دیگر حذف کرد:

```bash
rm -rf demo-frontend_v2
```

## محدودیت‌های دانسته‌شده

- این یک دموی فرانت‌اند است، نه فرانت‌اند نهایی محصول؛ صفحات ساده و بدون build tool پیاده‌سازی شده‌اند.
- در حالت دمو، داده‌ها فقط در حافظه مرورگر (در طول یک session) نگه‌داری می‌شوند و با رفرش صفحه بازنشانی می‌شوند.
- درخواست‌های sync-sap، purchase-requisition و pm-plans در `FMMS_API.yaml` هستند اما در این دمو (چون در بریف اصلی خواسته نشده بودند) پیاده‌سازی نشده‌اند؛ افزودن آن‌ها فقط نیازمند افزودن متدهای جدید به `js/api.js` است.
